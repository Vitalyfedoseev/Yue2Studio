# Music Studio · YuE2-3B

Локальный сервис генерации песен с веб-интерфейсом:

- **YuE2-3B** (m-a-p) — [huggingface.co/m-a-p/YuE2-3B](https://huggingface.co/m-a-p/YuE2-3B), лицензия CC-BY-NC 4.0 (некоммерческое использование весов)
- AR–NAR Mixture-of-Transformers (~4B): ABC-нотный план → семантические токены → flow-matching латенты → VAE → **48 кГц стерео FLAC**
- Длина песни следует за объёмом лирики (до ~5 мин); заявленное качество — уровень Suno v5 (WildSongBench)

## Запуск

```bash
./run.sh                      # слушает 0.0.0.0:8220 — доступно из домашней сети
                              # с других устройств: http://192.168.0.151:8220
YUE2_HOST=127.0.0.1 ./run.sh  # только локально
YUE2_VAE=m-a-p/YuE2-Vae-legacy ./run.sh  # VAE для бенчмарков (по умолчанию YuE2-Vae — субъективно лучше)
```

Для каверов по MIDI нужен **node** (обёртка конвертера в `third_party/midi2abc/`,
зависимости уже в `node_modules`; Deno не нужен); транскрипция аудио — SheetSage2
(снапшот в `third_party/sheetsage2/`, запускается из основного .venv; нужен вход
в HF с доступом к m-a-p/SheetSage2 и m-a-p/MERT-v2-FullSong) с фолбэком на
`third_party/audio2midi/venv` (basic-pitch, уже собран); везде нужен ffmpeg.

Изолированное окружение `.venv/` (torch 2.10.0+cu128, transformers 4.57.6 — жёсткие пины wheel'а
`yue2_infer`, ставить только так: `PIP_CONFIG_FILE=/dev/null .venv/bin/python /tmp/pip4.py install ...`,
см. памятку — системный pip.conf с NGC-индексом и IPv6-only DNS ломают установку).

## Развёртывание с нуля

### Требования

- Linux x86_64 (эталон — Ubuntu 24.04, Python 3.12), NVIDIA GPU от 16 ГБ VRAM
  (пик генерации 8–14 ГБ) с рабочим драйвером (`nvidia-smi` без ошибок);
- **node** ≥ 20 (конвертер MIDI→ABC; ищется в PATH, затем в nvm —
  `~/.nvm/versions/node/v*/bin/node`), **ffmpeg** в PATH;
- диск: ~10 ГБ venv + ~13 ГБ моделей в HF-кеше (YuE2-3B ≈ 8 ГБ, SheetSage2 + MERT ≈ 5 ГБ)
  + место под `outputs/` (≈12 МБ на минуту готовой музыки с латентами);
- вход в HuggingFace с доступом к **m-a-p** (YuE2-3B, YuE2-Vae, SheetSage2, MERT-v2-FullSong):
  `huggingface-cli login` от того же пользователя, что запускает сервис.

### Окружение `.venv/`

Жёсткие пины wheel'а `yue2_infer` (torch 2.10.0+cu128, transformers 4.57.6) — ставить только
с отключённым системным pip.conf (NGC-индекс и IPv6-only DNS ломают установку, см. памятку):

```bash
python3.12 -m venv .venv

PIP_CONFIG_FILE=/dev/null .venv/bin/pip install \
  torch==2.10.0+cu128 torchaudio==2.10.0+cu128 \
  --index-url https://download.pytorch.org/whl/cu128

PIP_CONFIG_FILE=/dev/null .venv/bin/pip install \
  transformers==4.57.6 scipy soundfile numpy fastapi "uvicorn[standard]"

# то, что wheel тянет криво — без зависимостей:
PIP_CONFIG_FILE=/dev/null .venv/bin/pip install --no-deps \
  pretty_midi mido mir_eval six importlib_resources decorator

PIP_CONFIG_FILE=/dev/null .venv/bin/pip install ./yue2_infer-0.1.5-py3-none-any.whl

# метрики и тесты (резолвер не трогает пины, проверено dry-run'ом):
.venv/bin/pip install librosa pytest httpx
```

Эталон версий — рабочая машина; при расхождении сверить `.venv/bin/pip list` с ней.

### Сторонние инструменты (`third_party/`)

| Каталог | Что это | Подготовка |
|---|---|---|
| `midi2abc/` | конвертер MIDI→ABC (Node, MIT) + `node_modules` | уже завендорен; при чистой копии — `npm install` внутри |
| `sheetsage2/` | основной движок аудио→ABC (m-a-p) | снапшот весов `SheetSage2/` положить руками (не версионируется); работает из основного `.venv`, при первом прогоне докачает MERT-v2-FullSong (~3 мин) |
| `audio2midi/` | фолбэк basic-pitch (отдельный venv) | рецепт установки — `third_party/audio2midi/README.md` (`--no-deps`, `numpy==1.26.4`, `setuptools<82`); без него аудио-фолбэк недоступен, SheetSage2 остаётся основным |

### Запуск и проверка

```bash
./run.sh                                   # 8220; модель качается при первом старте (~8 ГБ, единожды)
curl -s localhost:8220/api/health          # ждём ready:true (1–2 мин загрузки в VRAM)
.venv/bin/python -m pytest tests/ -q       # 24 теста без GPU
```

Переменные окружения: `YUE2_HOST` (по умолч. 0.0.0.0 — домашняя сеть),
`YUE2_PORT` (8220), `YUE2_MODEL`/`YUE2_VAE` (m-a-p/YuE2-3B и YuE2-Vae),
`YUE2_MAX_TOKENS` (22000 — бюджет на песню, ≈10–14 мин),
`YUE2_NO_MODEL=1` (тестовый режим без GPU). Обновления кода — перезапуск
(`pkill -f 'uvicorn [s]erver:app'` — со скобкой, иначе pkill убьёт собственный shell);
правки `static/` подхватываются по F5 без перезапуска.

## Инструкция по эксплуатации

### Подъём и остановка

```bash
setsid nohup ./run.sh > /tmp/yue2-web.log 2>&1 &   # поднять сервис (8220, домашняя сеть)
tail -f /tmp/yue2-web.log                          # лог
curl -s localhost:8220/api/health | head -c 200    # проверка: ready:true = модель в VRAM
pkill -f 'uvicorn [s]erver:app'                    # остановить (без самоматча — со скобкой!)
```

Модель грузится ~1–2 мин после старта: до этого `ready:false`, генерация и план отвечают 503.
После правок `server.py` нужен перезапуск; правки `static/` подхватываются сразу (F5).
Для экспериментов — второй инстанс: `YUE2_PORT=8221 ./run.sh` (или с `YUE2_NO_MODEL=1` без GPU).

### Обычный сценарий песни

1. **Стиль**: руками, кликабельным пресетом или из «Библиотеки стилей» (27 групп; ⚡-пресеты
   подставляют откалиброванный seed). Русские слова переводятся словарём при отправке —
   непереведённое подсвечивается предупреждением (модель лучше понимает английские теги).
2. **Голос**: каталог под стилем (пусто = вокал возьмётся из стиля; «Без вокала» = инструментал).
3. **Лирика**: секции `[verse]`/`[chorus]`… тегами-кнопками, по одному на строке; объём текста
   задаёт длину песни (лимит ≈ 10–14 мин). «без слов» + длина — инструментал нужного размера.
4. **Режимы**: cot full (модель пишет нотный план) / melody / off; guidance (пусто = авто);
   seed (−1 = случайный); драматургия build/wave/burst.
5. **Кнопки**: «Сгенерировать» — полный рендер; «Черновик» — ~15–20 с на прикидку;
   «×N» — веер вариантов (seed base+0..N-1, разные аранжировки одной формы);
   «План ABC» — построить нотный план без рендера: посмотреть, поправить в модалке,
   «Рендер по этому ABC».
6. Готовая песня — «динь» + карточка в истории. «Остановить» отменяет все активные задачи.

### Кавер по чужой мелодии

Блок «Кавер по MIDI или аудио»: `.mid` или аудио (mp3/wav/flac/…). Аудио разбирает SheetSage2
в нативный ABC (~10–60 с GPU), MIDI — конвертером. Ноты видны редактируемым полем — лишние
голоса можно вычистить, `.mid` скачивается. Дальше обычная генерация: модель поёт эту партитуру
(свой план не пишет). Чип «кавер по MIDI» и кнопка ABC — у готовой записи.

### Работа с готовой записью (карточка справа)

- **Секции** — лента структуры с секундами и RMS-громкостью; клик по секции = прослушать
  фрагмент (мгновенный VAE-декод латентов, без перегенерации).
- **Метрики** — темп/тональность/динамика/полосы/стерео; «сравнить с…» показывает дельты
  к любой другой записи.
- **DSP** — «Стена» (шум/песок/стена громкости) и «Кассета» (wow-детюн, срез верха, шип):
  крутилки → «Превью 15 с» (с 20-й секунды) или «Применить к треку»; варианты с дельтами
  метрик, скачиваются.
- **Овердаб** — сыграть ещё партию поверх записи: стиль (чипы инструментов или руками),
  гейн, текст (пусто = как у родителя). Приходит отдельной записью-потомком, микс с родителем —
  в её скачиваниях.
- Скачивание: MP3 320k / MP3 48k / FLAC / WAV / ABC. «↺ повторить» возвращает все параметры
  в форму (для веера — перегенерация с тем же сидом даст тот же трек). «✎ имя» переименовывает
  метку. «Удалить запись» стирает всё, включая латенты и производные.
- История: поиск по названию/тексту/стилю, ★-лайки с фильтром, клик = играть;
  плеер ходит ‹ › по списку и сам переходит к следующему треку.

### Обслуживание

- `outputs/` растёт: каждая запись ≈ FLAC (≈10 МБ/мин) + `latent.npy` (≈2 МБ/мин, float16) +
  производные в `<stem>.d/`. Чистка — удалением записей из UI (стирает всё) или руками.
- Тесты: `.venv/bin/python -m pytest tests/ -q` (без GPU).
- `static/stylelib.js` генерируется из исходников yue-studio (`node --input-type=module`,
  импорт `slotOptions/presets/groups.js`) — руками не править.

## Замеры (RTX 5060 Ti)

| Трек | Генерация | Скорость | Пик VRAM |
|---|---|---|---|
| 91 c (smoke) | 65 c | план 12 + семантика 30 + флоу 17 + VAE 5 | 7.9 ГБ |
| 67 c (API) | 51 c | ~75 ток/с семантика | 7.9 ГБ |
| 68 c (UI, рок) | 50 c | | 8.2 ГБ |

**~1.3–1.4× быстрее реального времени** (MiniMax-Music3 давал 0.17×). Модель живёт
в VRAM резидентно (~8 ГБ bf16+fp32), оффлоады не нужны.

**Лимит длины поднят**: бюджет семантических токенов 22000 вместо дефолтных 9000
(`YUE2_MAX_TOKENS`, env) — при такой лирике выходят треки ~10–14 минут, пик VRAM
доходит до ~14 ГБ (контекст модели 24576 токенов общий на всё: стиль+лирика+план+песня).

## UI

- **Очередь**: кнопка «Сгенерировать» всегда активна — задачи встают в FIFO на сервере; прогресс показывает обрабатываемая (первая), под ней «в очереди ещё: N»; каждая завершившаяся — «динь» + галерея. «Остановить» отменяет **все** активные задачи.
- **Черновик** — короткий рендер ~15–20 с (бюджет 450 токенов) на прикидку стиля/лирики. **×N** — веер вариантов с сидами base+0..N-1. **План ABC** — построить нотный план без рендера: в модалке можно править ABC и отрендерить по нему.
- **Драматургия** (селектор в ряду режимов): build (нарастание) / wave (волны) / burst (взрыв в финале — темп по секциям, вокал финальной припевной на октаву выше).
- **Инструментал**: тумблер «без слов» + длина (1/3/8/16 секций `[Instrumental]`).
- **Библиотека стилей** (под пресетами): 27 групп + 10 калиброванных пресетов с сидами (⚡ подставляет seed); «Мои стили» в localStorage. Русские слова в поле стиля при отправке переводятся словарём (384 пары ru→en), непереведённое — предупреждение.
- **Карточка трека** (правая колонка, в духе Suno): название, чипы (длительность/seed/VRAM/дата/черновик/дуга/овердаб), плеер с prev/next и автопереходом, блоки Стиль / Голос / Текст / **Секции** / **Метрики** / **DSP** / **Овердаб** / Тех.инфо; скачивание MP3 320k · 48k · FLAC · WAV · ABC; **↺ повторить** (вернуть параметры в форму), **✎ имя** (переименовать метку), **Удалить запись** (все артефакты, включая `.d/`).
  - **Секции** — лента секций с секундами и RMS-громкостью; клик = превью фрагмента (VAE-декод латентов).
  - **Метрики** — темп/тональность/динамика/полосы/стерео + дельты к любой другой записи («сравнить с…»).
  - **DSP** — цепочки «Стена»/«Кассета» (ffmpeg): крутилки, применение, превью 15 с, варианты с инлайн-дельтами метрик.
  - **Овердаб** — дочерняя генерация по партитуре записи (чипы партий, гейн, лирика родителя по кнопке); после рендера — автосмешанный файл в скачиваниях ребёнка.
- **История**: поиск по названию/тексту/стилю, фильтр ★, переименование, лайк; клик играет сразу.
- **Тема** — светлая/тёмная (◐ в шапке, localStorage).
- **Голос**: табы Женские / Мужские / Ансамбли / Без вокала, внутри — скроллящийся список (132px), у каждой строки «?» с всплывающим пояснением (fixed-тултип вне списка); выбор заполняет редактируемое поле «Голос» (на сервер клеится к стилю, в мете хранится отдельно).
- **Кавер по MIDI/аудио**: загрузка .mid или аудио (mp3/wav/flac/ogg/…) под лирикой. Аудио разбирает **SheetSage2** (m-a-p, `third_party/sheetsage2/`) — та же команда, что YuE2: выдаёт сразу нативный ABC (голоса Vocal/Ins, секции `% verse`, честный темп/тональность; `melody_only=True`), ~9 с GPU на 2-мин трек. MIDI и фолбэк — midi2abc (Node) и basic-pitch (отдельный venv). Ноты показываются редактируемым полем (извлечённый .mid можно скачать), уходят в модель как готовая партитура (`pipe(abc=..., cot="melody")`, план модель не пишет). Полномиксовая партитура сверх бюджета 15 тыс. токенов автоматически упрощается до моно-мелодии (только для basic-pitch-пути; SheetSage2 обычно компактна). У записи — чип «кавер по MIDI» и кнопки скачивания ABC; `.abc` лежит в outputs рядом с flac.
- Готовый трек НЕ запускается сам (только «динь»); клик в истории играет сразу.
- Пресеты стиля: метал (фолк/симфо-готик/нью+электроника/индастриал), панк (77/хардкор), техно (детройт/мелодик/дарк-EBM) + классика (фанк, синти-поп, баллада, рок, рэп, шансон).

## API

- `GET /api/health` — статус (+ `midi2abc.ok/node/ss2/a2m`, `metrics_ok` — librosa)
- `POST /api/midi2abc?title=…` — тело запроса: сырые байты .mid **или аудио** (mp3/wav/flac/…; не multipart). MIDI → ABC сразу (midi2abc); аудио → SheetSage2 → нативный ABC (`engine:"sheetsage2"`), при сбое — basic-pitch → MIDI → midi2abc (`engine:"basic-pitch"`) → `{abc, chars, engine, notes, midi_b64, duration_s, abc_tokens}`; ошибки — 422/503. Лимиты: MIDI ≤20 МБ, аудио ≤100 МБ / ≤15 мин
- `POST /api/generate` — `{style, voice, lyrics, title, cot, cfg_scale, seed, abc?, draft?, arc?}` → `{id}` (voice клеится к style на сервере, хранится в мете отдельно). `abc` — готовая партитура (кавер): требует `cot=melody|full`. `draft` — черновик ~15–20 с (бюджет 450 токенов). `arc` — драматургия `build|wave|burst` (правит темп по секциям и, для burst, поднимает вокал финала на октаву; несовместима с `abc` и `cot=off`)
- `POST /api/jobs/{id}/cancel` — **рабочая отмена**: queued снимается сразу, running — штатный `cancelled` пайплайна
- `GET /api/jobs/{id}` — прогресс (стадия, токены, ток/с, `pct` — честный % на семантике)
- `POST /api/plan` — `{style, voice, lyrics, cot, seed, arc?}` → `{abc, seconds, tokens, seed}` — план без рендера (GPU; 409 при идущей генерации)
- `GET /api/gallery/{stem}/score` — таймлайн партитуры (abcparse): такты/голоса/секции/секунды + `rms_sections`; кеш `<stem>.d/score.json`
- `POST /api/gallery/{stem}/preview` — `{from_sec, to_sec}` → превью фрагмента декодом латентов → `<stem>.d/preview-*.flac` (GPU; 409 при генерации)
- `POST /api/gallery/{stem}/analyze?fresh=` — librosa-метрики (темп, тональность, динамика, полосы, стерео); кеш `<stem>.d/metrics.json`
- `GET /api/dsp/chains` — описания цепочек (wall/wall-lite/tape + параметры)
- `POST /api/gallery/{stem}/dsp` — `{chain, params, preview}` → `<stem>.d/dsp[-preview]-<chain>.flac` + метрики варианта; `GET …/dsp` — список вариантов
- `POST /api/gallery/{stem}/overdub` — `{style, lyrics?, gain=0.5, seed?}` → джоба-потомок по партитуре записи; после рендера автоматически смешивается с родителем (`overdub_of`, `<parent>.d/overdub-*.flac`)
- `POST /api/gallery/{stem}/rename` — `{title}` (только метка в мете)
- `GET /api/outputs/<имя>.flac/mp3|wav` — MP3 320k/48k и WAV PCM16 (с кешем)
- `DELETE /api/gallery/<stem>` — удалить запись целиком: flac+json+кеш mp3+abc+score.abc+latent.npy+папка `<stem>.d/`
- `GET /api/gallery`, `GET /outputs/*`

## Артефакты записи

Каждая генерация, помимо `<stem>.flac/.json/.mp3`, теперь пишет:

- `<stem>.score.abc` — модельный нотный план (и при внешнем `abc=`) — база для таймлайна и овердаба;
- `<stem>.latent.npy` — латенты float16 (25 кадров/с, ~2 МБ/мин) — база для превью фрагментов;
- `outputs/<stem>.d/` — производные: кеши score/metrics, превью, DSP-варианты, овердаб-миксы.

Записи, сделанные до появления этих артефактов, работают как раньше — превью/таймлайн/овердаб для них вернут 404.

## Заметки

- Каверы по MIDI: `POST /api/midi2abc` → готовая ABC подаётся в `pipe(abc=..., cot="melody")` (UI: блок «Кавер по MIDI» под лирикой). Длинная партитура съедает общий контекст 24576 — сервер отклоняет генерацию, если на песню остаётся <1000 токенов. Полный транскрипт аудио в ABC (SheetSage2) по-прежнему только через API пайплайна.
- Тег секции — на отдельной строке.
